1. Overview

Once a day, the script checks a list of contractor accounts in your organization and sends an email warning if any of those accounts are about to expire. It looks 14 days ahead by default. If nothing is expiring, no email is sent.

Why it exists

Contractor accounts in your organization's user directory (called Active Directory) expire on a set date. If no one notices in time, the contractor loses access to systems and work stops. This script gives advance warning so the account can be renewed before that happens.

How it works

The script runs automatically on a schedule. It reads from a group called Contractors in your organization's directory, finds any accounts expiring within the next 14 days, and sends one summary email to the addresses you configure. If no accounts are expiring soon, it quietly finishes without sending anything.

2. Requirements

Before the script can be used, the following must be in place:

  • A Windows server or computer that is connected to the company network and can access the organization's user directory (Active Directory). This is typically any domain-joined Windows server.
  • PowerShell — included with Windows; no separate installation needed.
  • RSAT (Remote Server Administration Tools) — a free Windows add-on that lets PowerShell read user account information. Your IT administrator can install this. On Windows Server, it is usually already available.
  • A Microsoft 365 shared mailbox for the script to send email from. A shared mailbox does not require a license. Ask your IT administrator if you do not already have one set up.
  • A security permission set up in Microsoft's cloud portal — this tells Microsoft 365 that the script is allowed to send email on behalf of your organization. This is a one-time step covered in the next section. An administrator account is required.

3. Setting Up the Security Permission (App Registration)

Before the script can send email, it needs a permission slip from Microsoft. This is called an App Registration. Think of it as registering the script as a trusted application that is allowed to send email through your organization's Microsoft 365 account. This only needs to be done once.

You will need an administrator account to complete these steps. If you do not have one, ask your IT administrator to do this part for you — they will need to give you three values at the end: Tenant ID, Client ID, and the security credential.

Step-by-step instructions

  1. Sign in to Microsoft's cloud portal at entra.microsoft.com using an administrator account.
  2. In the left navigation, click App registrations, then click New registration.
  3. Give the app any name — for example, Contractor Expiration Alert. Leave all other settings at their defaults and click Register.
  4. You will land on the app's Overview page. Copy and save two values from this page:
    • Application (client) ID
    • Directory (tenant) ID
  5. Click API permissions in the left navigation. Click Add a permission, choose Microsoft Graph, then choose Application permissions.
  6. In the search box, type Mail.Send. Check the box next to Mail.Send and click Add permissions.
  7. Click Grant admin consent for [your organization] and confirm. The status column next to Mail.Send should change to a green checkmark.
  8. Click Certificates & secrets in the left navigation. Click New client secret. Give it any description, choose an expiration of 24 months, and click Add.
  9. Important: Copy the secret's Value immediately — it is only displayed once. Note the expiration date somewhere safe (a calendar reminder 30 days before it expires is recommended).

You now have the three values needed for first-time setup: Tenant ID, Client ID, and the security credential. Keep these in a secure place.

What is the security credential? Think of it like a password for the script. It proves to Microsoft that the script has permission to send email on behalf of your organization. It expires after the period you chose (typically 24 months) and must be renewed — see Section 8 — Renewing the Security Credential for instructions.

4. The Contractors Security Group

In your organization's user directory (Active Directory), there is a group called Contractors. The script monitors every account that is a member of this group — and only those accounts. It does not look at every user in the organization.

What this means for you

  • If a contractor account is not in the Contractors group, the script will not warn about it — even if it is about to expire.
  • If a contractor account is in the group but has no expiration date set, the script flags it in a separate section of the email as a potential oversight. Every contractor account should have an expiration date.
  • Accounts that are disabled are ignored — the script only checks active accounts.

Managing group membership

Group membership is managed by your IT administrator. If a contractor should be receiving expiration warnings but is not appearing in the alert emails, ask IT to:

  1. Add the contractor's account to the Contractors group in Active Directory.
  2. Make sure an expiration date is set on that account.

5. Script Options

The script accepts several options that control how it behaves. The two required ones must be provided every time the script runs (they are included in the scheduled task command). All others are optional.

Option What it does Required? Default
-GroupName The name of the security group to monitor. This must match exactly what is in Active Directory. Yes —
-To Who receives the alert email. You can list more than one address, separated by commas. Yes —
-Cc Additional people who receive a copy of the email. Optional. No None
-WarnDays How many days ahead to look for expiring accounts. No 14
-Setup Runs the first-time setup wizard. Also used when updating the security credential after it expires. No Off
-ReportOnly Preview mode — shows what the email would say without actually sending it. Useful for testing. No Off
-Diagnostics Prints extra detail to the screen while running. Useful when troubleshooting a problem. No Off
-LogHistory How many days of log files to keep before they are automatically deleted. No 30
-SkipUpdateCheck Skips checking online for a newer version of the script at startup. No Off
